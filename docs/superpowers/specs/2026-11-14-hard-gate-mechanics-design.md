## 0. 一句话

推荐做法：**一句一判、三级重试、照读算通过、四层降级、本地信息槽为主判、发送必须由玩家亲手按下**——
硬门禁只落在「作者显式标注 + 属于五类关键 + 本地可判定」的**单句发言**上；判定只看信息槽是否到位，不看语法、口音和语气；任何一条失败路径都必须能把故事继续推下去。

---

## 1. 定义：什么算一次硬门禁

### 1.1 三个必要条件（全部满足才算）

1. **叙事资格**：这句发言属于 11-12 文档 §6.1 的五类之一——真相揭露 / 生死 / 关系转折 / 不可撤回的承诺或仪式 / 语言本身就是行动。
2. **数据标注**：该句所在 beat 是关键 beat，且该句在数据层标了 `gate.type = "hard"`。
3. **可判定性**：该句有作者写好的必需信息槽与可接受说法；本地跑得动，不依赖 AI。

少任何一条，这句只能是软门禁。

### 1.2 「一次硬门禁」的粒度

- 一次硬门禁 = **一个门禁句 + 一次完整的「前置提示 → 作答 → 核对 → 发送 → 判定 → 处置」循环**。
- 不是一条 NPC 消息，也不是整个 beat；同一个门禁句下可以有多轮玩家输入（重说）。
- **一个 beat 最多一个硬门禁句**；同 beat 其余台词一律软门禁。
- 玩家在门禁句上的输入只判这一句，不合并判定前后的软台词。

### 1.3 明确不允许做硬门禁的位置

- 选项层（`choice.options`）：选哪个分支永远可选，语言能力不能锁分支。
- 读消息、听语音、看场景：没有产出的地方不判。
- 非关键 beat、普通日常对话。
- 作者没写信息槽、或槽位无法本地匹配的句子。
- 没有前置信号的突袭判定。

## 2. 与软门禁的边界（避免同一处既软又硬）

### 2.1 互斥表

| 维度 | 硬门禁 | 软门禁 |
|---|---|---|
| 判定对象 | 单句发言是否「发得出去」 | 整句表达是否得体、信息是否完整 |
| 判定时机 | 玩家按下发送时拦截（系统不代发） | 发送后或随剧情结算 |
| 判定源 | 本地信息槽 → AI 增强 | AI 判分 / 叙事规则 / 不判 |
| 失败表现 | 发不出去，进入重试阶梯 | 照常发出，NPC 反应变冷、关系/线索受影响 |
| 剧情影响 | 决定这一句的落点，不决定分支能否选 | 决定风味、关系、后续台词冷暖 |
| 配额 | 每章 2–3 个 | 不限 |
| 数据标注 | `gate.type = "hard"` + 槽位 | 无 `gate` 字段，或 `gate.type = "soft"` |

### 2.2 单一真相源

- 一句台词是软是硬，**只由数据里的 `gate.type` 决定**，运行时不做语义推断。
- 同一句不可能既软又硬；不允许出现「本地判一次、AI 再判一次」的双重判定。
- 硬门禁通过后，后续 NPC 的反应仍然可以走软门禁的表达规则，但那是**下一句的事**，不回头改判已发送的门禁句。

### 2.3 边界情形的处理

- 门禁句里的语气不合适（太冲、太软）→ **仍算通过**，风味层记录，后续台词变冷或变暖。
- 信息到位但语法有错、语序颠倒、拼写错误 → **算通过**。
- 信息缺失、否定说反、数量说错 → **算没到位**（详见 §4.4）。
- 玩家在 R3 照读参考译文并发送 → **算通过**（A2 已定），按正常通过落账。
- 玩家主动选择「沉默 / 说不出口」→ 不算判定失败，属于合法叙事出口，按出口后果推进。

## 3. 聊天流中的形态

### 3.1 玩家看到什么

**前置信号（作答前，一次性，叙事化）**

- NPC 气泡出现一次停顿（如「……」单独一条或延迟一行）。
- 环境音 / 背景动效变化（如潮声停半拍）。
- 输入框进入「收不回」态：描边变重、占位文案改为「这句话说出去就收不回」。
- 可选：输入区左上角出现一个 8×8 像素角标（沿用现有像素图标语言），表示「关键台词」。

**不允许的前置信号**：红色警告条、「本题为考试」、「请认真作答」这类工具化文案。

**门禁句现场**

- 提示面必须显示那句原意，且使用**与输出相反的语言**：角色说英语时给中文原意，角色说中文时给英文原意。
- 玩家要输出的是**角色当前使用的语言**（与角色同语），不是提示语言。
- 参考译文（输出语言版本）不可见，直到 R3。
- 输入区保留正常打字、录音、识别、重听能力。
- 出现一个次要的叙事化出口（如「说不出口」），R1 之后才出现，且不抢主按钮。
- R3 展开参考译文后，同时提供「照读并发送」与「沉默」两条合法路径；**照读是通过路径**，不是惩罚出口。

### 3.2 玩家能做什么 / 不能做什么

| 能做 | 不能做 |
|---|---|
| 打字回复 | 查看参考译文（R3 前） |
| 录音 + 实时识别 | 跳过本句 / 跳过本 beat |
| 重听 NPC 语音、回看对话 | 切换中英模式或练习方向 |
| 重说（受重试上限约束） | 粘贴自定义句、打开 SRS 队列 |
| 在输入框核对、编辑、重听后决定是否发送 | 系统自动发送 / 自动清空输入 |
| R3 后照读参考译文并发送（算通过） | 通过返回键绕过判定 |
| 选择叙事化出口（沉默 / 说不出口） | 未按发送前让剧情自动推进 |

- **无倒计时**（沿用 11-12 §9 的「默认无倒计时」）。
- 打字永远是合法路径；语音只是增强。

### 3.3 状态机

| 状态 | 进入条件 | 玩家可见 | 可用动作 | 出口 |
|---|---|---|---|---|
| `arrive` | 门禁句出现 | 气泡 + 前置信号 | 读、听、回看 | —— |
| `compose` | 玩家开始输入 / 录音结束 / 识别出文字 | 文本只落输入框，不自动发送 | 打字、编辑、重听、重说 | 出口按钮（R1 后） |
| `review` | 输入框已有内容 | 文本可改、可删、可重说 | 核对、编辑、重听 | 按下发送才进入判定 |
| `judging` | 玩家按下发送 | 轻量「……」等待 | 无（本地 <100ms，AI 可选 ≤1.5s） | 超时落本地结论 |
| `passed` | 判定通过（含 R3 照读） | 消息发出，NPC 回应 | 继续剧情 | —— |
| `retry` | 未到位 | 缺失信息类别提示；文本保留可编辑 | 修改后再次发送 / 重说 | 进入下一级提示 |
| `exit` | R3 或主动出口 | 参考译文 + 照读 / 沉默 | 照读发送（通过）/ 沉默发送（叙事收束） | 发送后推进剧情 |

### 3.4 发送前必须人工确认（明文规则）

1. 录音结束或语音识别给出文字后，结果**只填入输入框**，不自动发送、不自动判定、不自动清空。
2. 玩家可以在输入框里核对、删改、补字、重听 NPC 语音、重听自己的录音，也可以重录或重说。
3. **发送是唯一推进动作，且始终由玩家亲手按下**；系统不得代按、不得倒计时自动发送、不得「识别完成即发送」。
4. 不做二次弹窗确认：确认动作就是「按下发送」本身，避免多一道打断。
5. 判定发生在按下发送的瞬间；按下之前的所有修改都不产生后果，按下之后消息锁定并成为既成事实。
6. 与「发送后不可撤回」的衔接：
   - **按下发送前**：完全可逆，文本、录音、重说都不推进剧情、不落账；
   - **按下发送后**：消息进入对话流，判定结果与 `failEffect` 一并落账，不可撤回、不可改写；
   - **判定未通过时**：文本保留在输入框，玩家可继续修改后再次发送——这属于「重说」，不是新消息；
   - **R3 照读同理**：玩家看到参考译文后，仍要自己按下发送才算通过。
7. 识别错误不需要重录：直接在输入框改字，改完再发送；A8 的 +1 次宽限照常有效。
8. 无例外场景：不存在任何自动发送路径（包括剧情演出、语音消息、倒计时）。

## 4. 判定依据：信息槽

### 4.1 槽位定义

必需槽（默认五项，来自 11-12 §8.1）：

| 槽 | 含义 | 取值类型 | 例子 |
|---|---|---|---|
| `who` | 谁：主体或对象 | 实体别名集合 | 「井婆」「the woman in the well」 |
| `action` | 做了什么：核心动作或事件 | 动作短语集合 | 「不回头」「not look back」 |
| `time` | 时间：时态或时间状语 | 时间表达集合 / 时态标记 | 「去年」「last year」「已经」 |
| `polarity` | 否定关系 | `positive` / `negative` | 「没有」「not」「n't」「never」 |
| `quantity` | 数量 | 数字或量级 | 「三根」「three」「全部」「all」 |

可选槽（只影响反馈，不影响通过）：

| 槽 | 含义 | 例子 |
|---|---|---|
| `place` | 地点 | 「滩口」「the beach mouth」 |
| `condition` | 条件 | 「如果」「if」「unless」 |
| `modality` | 情态（请求 / 命令 / 承诺） | 「能不能」「could you」 |

规则：**必需槽由作者按句子逐条勾选，不默认全开**。短句可能只需要 `who + action`；含数字的句子必须加 `quantity`；含否定的句子必须加 `polarity`。

### 4.2 作者标注，不做运行时语义猜测

- 数据里显式写 `required` 槽列表与每槽的 `accept` 说法。
- `accept` 按**输出语言**配置：`zh2en` 只列英文说法，`en2zh` 只列中文说法；不得混入提示语言。
- 判定对照的是提示面那句原意的信息槽，不要求与参考译文逐字一致。
- `accept` 支持三类写法：字符串（规范化后包含匹配）、正则、数字归一映射。
- 运行时**只做规范化与匹配**，不调用模型去「理解」意思；AI 只做「扩充可接受变体」的增强（§6.1）。

### 4.3 规范化管线

按顺序执行，全部本地完成，只处理玩家输出的文本（提示语言不参与规范化）：

1. 小写化，去首尾空白。
2. 去标点（保留小数点与连字符中的数字）。
3. 缩写展开：`don't → do not`、`can't → cannot`、`it's → it is`。
4. 数字统一：`three → 3`、`三 → 3`；中文量词剥离（「三根」→ 3 + 单位）。
5. 词形归并：规则表把 `went → go`、`looked → look`、`has been scraped → scrape`；只做有限表，不追求全量词法。
6. 同义替换：按 `accept` 词表命中，不做通用同义词库。
7. 否定识别：在小句范围内找否定词（`not / no / never / n't / 没有 / 不 / 别 / 未`），确定 `polarity`。

**作用域简化**：以逗号、分号、句号为界切小句；否定词只翻转所在小句的极性。跨小句的否定（「不是他不想来，是他来不了」）由作者在 `accept` 里直接列出可接受整句，不交给通用算法。

### 4.4 匹配与通过条件

判定顺序固定：

1. **极性检查**：`polarity` 必需且说反 → 直接判「没到位」，不再看其它槽。
2. **必需槽逐项检查**：任何一个必需槽未命中 → 「没到位」，记录缺失槽名。
3. **数量检查**：`quantity` 必需且数字不一致 → 「没到位」。
4. 全部必需槽命中 → **通过**。

补充规则：

- 判定对象是玩家输出的目标语言文字；对照的是提示面那句原意，不要求与参考译文逐字一致。
- 可选槽未命中不影响通过，只用于生成更具体的反馈。
- 允许语序错误、语法瑕疵、口音转写错误、拼写错误；规范化后能命中即算。
- 空输入、纯语气词、明显无关内容 → 「没到位」，缺失槽记为全部必需槽。
- 语音识别文本与打字文本走同一套判定，不区别对待。

### 4.5 判定输出

```js
{
  pass: false,
  failedSlots: ['who', 'quantity'],   // 只给槽名，不给答案词
  polarityReversed: false,
  source: 'local' | 'ai' | 'self' | 'degraded'
}
```

- `failedSlots` 只用于生成提示文案，禁止把 `accept` 里的词直接显示给玩家。
- 判定耗时目标：本地 <100ms；AI 增强可选，超时 1.5s 直接采用本地结论。

## 5. 没到位之后

### 5.1 三级重试阶梯（已定）

| 级别 | 触发 | 提示内容 | 是否给答案 |
|---|---|---|---|
| R1 | 第 1 次未到位 | 具体但不完整：只点缺失的信息类别（「你还没说清是对谁说的」） | 否 |
| R2 | 第 2 次未到位 | 结构提示：列出这句话需要哪几个信息（「谁 + 做了什么 + 是否定」） | 否 |
| R3 | 第 3 次未到位 | 展开输出语言的参考译文，并提供「照读发送」与「沉默」两条路径 | 是 |

- 每级文案不重复；同一级内多次失败换用不同措辞。
- **照读参考译文算通过**（A2 已定）：不必再独立产出，照读本身也是一次开口；发送后按通过记一次练习。
- 「沉默」是叙事出口，不算通过，也不算判定失败。
- 照读同样要玩家自己按下发送；系统不代发。
- 提示必须叙事化（NPC 的反应、环境变化），不能弹出「错误：缺少主语」式工具文案。

### 5.2 剧情是否推进 / 可逆性

| 时点 | 是否推进剧情 | 是否可逆 |
|---|---|---|
| 按下发送前（含 R1/R2 重说、输入框编辑） | 不推进 | 完全可逆，可反复改、反复说（受上限约束） |
| 按下发送、判定通过（含 R3 照读） | 推进 | 不可撤回 |
| 按下发送、选择「沉默」出口 | 推进 | 不可撤回 |
| 发送后 | 按结果落 flag，后续 beat 继续 | 本句不再改判；章节回退属于 O11 |

- 硬门禁失败**不结束游戏**（A5 已定：第一版不做死亡节点）。
- 失败只写叙事 flag：关系变化、线索缺失、后续台词冷暖；**不扣券、不直接扣羁绊数值**（A4 已定）。
- 照读通过后按正常通过落账，不额外标为失败；「沉默」出口的后果由 `failEffect` 定义。
- 出口发送后，本 beat 剩余台词仍按软门禁继续，不因一次失败把整段变成惩罚关。

### 5.3 记录、券与 SRS（已定）

| 项 | 已定做法 |
|---|---|
| 练习记录 | 首次作答记 1 条；重说不新增记录（A3） |
| 券 | 首次作答照常计；重说不重复计（A3） |
| SRS | 只按首次判定结果入队；重说不改变档位（A3） |
| R3 照读 | **算通过**，记 `ok` 并标注「照读参考」；入队档位与普通通过一致（A2） |
| 出口沉默 | 不记练习记录，只落剧情 flag |

补充：照读的 `ok` 保留「reference」标记，便于统计时区分「独立产出通过」与「照读通过」，但两者在剧情推进上等价。

## 6. 离线与 AI 不可用时的降级

### 6.1 判定链（按顺序，前一步成功即止）

1. **本地信息槽判定**（永远可用，无网络依赖）。
2. **AI 增强**（在线 + 有 key）：只用于把「本地未命中」升级为「命中」（补充合法意译），**不能把本地通过改成不通过**。
3. **自评兜底**（仅在识别文本为空、且玩家无法打字时）：玩家确认「我说到了 / 我没说到」，界面明确标注「本次为自评」。
4. **降级为软门禁**（所有判定路径都不可用）：消息直接发出，故事记下「你说得不够清楚」，继续推进。

### 6.2 绝不卡死的四条硬规则

1. 每条判定路径都必须有出口（重说上限到了也给出口）。
2. 语音识别失败不影响打字；识别错误不直接判失败，给一次宽限（A8）。
3. 断网时 AI 步骤**跳过**，不报错、不阻塞。
4. 运行时发现门禁句缺槽位或词表 → 立即降级为软门禁并告知玩家，不进入无法判定的死循环。

### 6.3 降级告知

- 不弹窗；在输入区或 NPC 回应行内用一行小字说明：
  - 「本次为自评」
  - 「本次未做精确判定」
  - 「识别不稳定，已按你说到的意思处理」
- 告知必须在发送前或发送同时出现，不能事后才说。

### 6.4 降级矩阵

| 场景 | 判定源 | 结果 | 玩家看到 |
|---|---|---|---|
| 在线 + 有 key + 本地通过 | local | 通过 | 正常发送 |
| 在线 + 有 key + 本地未过 + AI 认可 | ai | 通过 | 正常发送 |
| 在线 + 本地未过 + AI 不认可 | local | 未过 | R1/R2 提示 |
| 离线 + 本地未过 | local | 未过 | R1/R2 → R3 照读（通过）/ 沉默 |
| 识别文本为空 + 可打字 | local | 按打字判定 | 正常 |
| 识别文本为空 + 不可打字 | self | 自评 | 「本次为自评」 |
| 门禁句数据缺槽位 | degraded | 软门禁 | 「本次未做精确判定」 |

## 7. 内容层表达（作者怎么写）

### 7.1 数据 schema 草案

在现有场景 JSON 的 `lines[]` 上追加可选字段 `gate`；不标 = 软门禁，旧数据零迁移。

```json
{
  "id": "scn04_07",
  "dir": "zh2en",
  "speaker": "你",
  "intent": "拒绝井底那个声音的召唤",
  "zh": "我不会回头，你也不是他。",
  "en": "I'm not turning around — and you're not him.",
  "difficulty": 4,
  "tags": ["否定", "拒绝"],
  "gate": {
    "type": "hard",
    "category": "relationship_turn",
    "required": ["who", "action", "polarity"],
    "accept": {
      "who": ["him", "the voice"],
      "action": ["turn around", "look back"],
      "polarity": "negative"
    },
    "hints": {
      "r1": "你还没说清这句话是对谁说的。",
      "r2": "先说清「谁」，再说「回不回头」。",
      "r3": "参考译文：I'm not turning around — and you're not him."
    },
    "reference": "I'm not turning around — and you're not him.",
    "failEffect": { "flag": "looked_back", "note": "后续井婆台词转冷" }
  }
}
```

字段约定：

| 字段 | 必填 | 说明 |
|---|---|---|
| `dir` | 是 | `zh2en` = 提示中文、输出英文（角色说英语）；`en2zh` = 提示英文、输出中文（角色说中文） |
| `gate.type` | 是 | `hard` / `soft` |
| `gate.category` | hard 必填 | 五类枚举：`truth_reveal` / `life_death` / `relationship_turn` / `irreversible_pledge` / `speech_act` |
| `gate.required` | hard 必填 | 必需槽名数组，至少 1 个 |
| `gate.accept` | hard 必填 | 每个必需槽在**输出语言**中的可接受说法 |
| `gate.hints` | hard 必填 | r1 / r2 / r3 三级提示 |
| `gate.reference` | hard 必填 | R3 展示的**输出语言**参考译文 |
| `gate.failEffect` | hard 必填 | 出口发送后的剧情后果（flag + 说明） |
| `gate.selfAssess` | 否 | 是否允许自评兜底，默认 true |

### 7.2 配额在内容层的表达

- 章节（或 beat 序列）级加 `gateBudget`：

```json
{ "id": "ch02", "gateBudget": { "min": 2, "max": 3 } }
```

- 校验器统计本章 `gate.type === "hard"` 的句子数，超出 `max` 报错，低于 `min` 给出警告。
- 相邻两个硬门禁之间至少隔一个软场景；校验器按 beat 顺序检查，不满足报错。
- 配额是**内容层约束**，不在运行时动态调度。

### 7.3 作者工作流

1. 编剧先出门禁表：beat、门禁句、五类归属、必需槽、三级提示、失败后果。
2. 编辑校验：类别合法、槽位可本地判定、每章预算、提示不泄题。
3. QA 跑门禁矩阵：在线/离线 × 打字/语音 × 通过/未过/出口，逐条过。

### 7.4 校验规则清单（建议随实现加到脚本）

1. `gate.type` 只能是 `hard` / `soft`。
2. `hard` 必须有 `category`，且在五类枚举内。
3. `hard` 的 `required` 非空，且每个槽都有 `accept`。
4. `hard` 必须有 r1 / r2 / r3 三级提示与 `reference`。
5. `hard` 必须有 `failEffect`。
6. 同一 beat 内 `hard` 数量 ≤ 1。
7. 每章 `hard` 数量在 2–3 之间。
8. 相邻硬门禁之间至少一个软场景。
9. `hints.r1` / `r2` 不得包含 `accept` 中的答案词（防泄题）。

## 8. 推荐方案总览（含已拍板结论）

| 维度 | 结论 | 说明 |
|---|---|---|
| 判定粒度 | 单句 | 与「发送即说话」的核心动作一致 |
| 主判源 | 本地信息槽 | 离线可用、可预测、成本为零 |
| AI 角色 | 只升级、不否决 | 避免网络成为门神 |
| 通过标准 | 五项必需槽全中，极性优先 | 对应 11-12 §8.1 的「信息到位」 |
| 照读路径 | R3 照读算通过（A2） | 不打击开口积极性，照读也是一次学习 |
| 发送控制 | 始终由玩家亲手按下 | 录音/识别结果只落输入框，不自动发送 |
| 失败表现 | 三级提示 + 照读 / 沉默出口 | 压力可控，不卡死 |
| 重试上限 | 3 次后只留照读与出口（A1） | 防疲劳，保留通过路径 |
| 剧情推进 | 按下发送前不推进，发送后不可撤回 | 保持因果清晰 |
| 失败代价 | 只写叙事 flag，不扣数值（A4） | 符合「失败改变路径，不结束游戏」 |
| 死亡节点 | 第一版不做（A5） | 与「绝不卡死」承诺一致 |
| 打字 / 语音 | 同权（A6） | 无障碍与判定公平 |
| 显式跳过 | 不提供（A7） | 只保留叙事化出口 |
| 识别宽限 | 出错多给一次重试（A8） | 语音路径容错 |
| 软硬边界 | 数据字段唯一决定 | 杜绝双判定 |
| 配额 | 每章 2–3，硬上限（A9） | 防通胀，作者可控 |
| 降级 | 本地 → AI → 自评 → 软门禁 | 四层兜底，永不卡死 |

## 9. 决策结果（2026-11-14 已拍板）

O1 无剩余待拍板项。

| 编号 | 岔路口 | 已定结果 | 备注 |
|---|---|---|---|
| **A1** | 重说上限 | 3 次后只留照读与出口 | 与 v1 推荐一致 |

| **A3** | 重说是否重复记录 / 计券 | 只记首次，重说不计 | 与 v1 推荐一致 |
| **A4** | 失败是否直接影响羁绊 / 关系数值 | 只写 flag，不扣数值 | 与 v1 推荐一致 |
| **A5** | 是否设不可逆死亡节点 | 第一版不做 | 与 v1 推荐一致 |
| **A6** | 打字与语音是否同权 | 同权 | 与 v1 推荐一致 |
| **A7** | 是否提供「跳过本句」 | 不提供，只给叙事出口 | 与 v1 推荐一致 |
| **A8** | 识别错误导致的失败是否给宽限 | +1 次重试 | 与 v1 推荐一致 |
