## 0. 一句话

**语言 / 翻译只是本作的交互方式，与世界观毫无关系。** 角色用什么语言，玩家就用什么语言把话发出去；屏幕上给玩家的提示永远是另一种语言的原意。界面语言、提示语种、输出语言三者分开定义；章节进行中不切换，一章结束回到主界面后才能切换。

---

## 1. 定位：先明确不做什么

- 本作要练英语，所以玩家必须用**角色当前使用的语言**发言。这是一条交互约束，不是世界观设定。
- 提示面显示的是「你此刻想表达什么」的**另一种语言原意**，不是让玩家照着提示语言直接发。
- 参照普通中文游戏：玩家发中文就能互动；本作只是把「发什么语言」变成可选的练习方向。
- 不做任何设定层解释：不写怀表、听潮、契约、翻译能力，不写「换一种听法」，不写进主线，也不设相关谜底。
- 语言差异只存在于交互层（听到什么、要说什么、按什么语言判定），**不产生剧情分支**。
- 不新增「语言系统」类玩法；它就是输入与判定的一条规则。

---

## 2. 机制定义

| 概念 | 定义 |
|---|---|
| 界面语言 | 菜单、按钮、系统提示的语言，独立设置 |
| 提示语种 | 屏幕上「你此刻想表达什么」那句原意的语言；始终与输出语言相反 |
| 输出语言 | 玩家实际打字 / 说话并发送的语言；必须与角色当前使用的语言一致 |
| 方向 `zh2en` | 提示中文 → 输出英文 → 角色说英语 |
| 方向 `en2zh` | 提示英文 → 输出中文 → 角色说中文 |

- 角色说英语时：提示中文原意，玩家翻成英语发出；语音识别、判定、TTS 都按英语。
- 角色说中文时：提示英文原意，玩家翻成中文发出；语音识别、判定、TTS 都按中文。
- **输出语言 = 角色语言 ≠ 提示语种**；中文只出现在提示面（`zh2en` 时），不会成为玩家的输出。
- **「界面语言」「提示语种」「输出语言」三者分开定义**，不合并成一个「语言设置」（已定）。
- 同一句的双语文本语义等价；方向只决定「哪一边是提示、哪一边是输出」。

---

## 3. 切换时机（已定）

- **章节进行中不切换。**
- **一章结束、回到主界面后**才允许切换语言方向。
- 章节内的设置入口可以展示当前方向，但为只读状态，并说明「本章结束后可切换」。
- **未发送的作答禁止切换**（章节边界同样适用：作答中不切）。
- 已发送的消息不重判、不改写；切换只影响之后的章节。
- 切换不重置章节进度、羁绊、SRS、券等任何进度。
- 具体交互细节（入口位置、提示文案、是否需要二次确认）后续再议；本文档只锁定「章节边界切换」这一条。

---

## 4. 交互一致性规则

1. 界面语言 ≠ 提示语种 ≠ 输出语言，三者分开定义，不合并成一个开关。
2. 提示语种始终与输出语言相反；输出语言必须与角色当前语言一致。
3. 章节进行中不可切换；章末回主界面后可切。
4. 作答未发送时禁止切换。
5. 已发送消息不重判、不改写。
6. 切换不重置任何进度。
7. 记录按「句子 ID + 方向」独立存储，互不覆盖。
8. 硬门禁按玩家**输出语言**判定；同一句双向的 `accept` 语义必须一致。
9. 双语语义等价，不制造剧情分支。
10. NPC 性格与说话方式在双语中保持一致。
11. 双语内容尺度一致。
12. 专有名词按统一表处理。

---

## 5. 与其它模块的关系

### 5.1 与 O1 硬门禁

- 判定只针对玩家产出的**输出语言**：`zh2en` 判英文，`en2zh` 判中文；提示语言不参与判定。
- 信息槽的 `accept` 按输出语言配置；对照的是提示面那句原意的信息槽，不要求与参考译文逐字一致。
- 同一句的双向配置必须语义一致。
- 章节内不切换，因此不存在「一章里判定方向漂移」的问题；已发送结果更不会重判。

### 5.2 与 O2 内容尺度

- 双语内容使用同一尺度：英文版不得比中文版更露骨或更血腥。
- 章节内容提示、低恐怖开关的文案跟随**界面语言**，不跟随练习方向。
- 当前目标为 12+（见 O2），双语都按 H2 / R2 上限执行。

### 5.3 与记录 / SRS

- 记录键为「句子 ID + 方向」；同一句的中→英与英→中视为两条独立练习。
- 切换方向不清空已有进度，也不把另一方向的成绩合并过来。
- 抽卡解锁句的方向由句子自身 `dir` 决定，不跟随全局设置。

### 5.4 与音频

- 中文语音、英文语音各自预生成；切换方向即切换播放语言。
- 英文 `they` 等非二元表达按正常发音处理（见 O2 §6.1）。
- 语音失败时回退到文字，不阻塞流程。

## 6. 双语资产与成本

| 项 | 要求 | 备注 |
|---|---|---|
| 台词 | 每句 `zh` + `en` 双语 | 现有数据结构已具备 |
| 门禁配置 | 每个方向一套 `accept` | 双向语义必须一致 |
| 提示文案 | 按提示语种各一套 | 提示不泄题；提示语种 = 输出语言的反向 |
| CG | 画面避免依赖文字；必要文字做双语层 | C1 / C2 皆可 |
| UI | 界面语言独立配置 | 不随练习方向变 |

成本控制：优先保证关键句（门禁句、章节首尾、关系节点）的双语质量；普通句允许先机器辅助、后人工校对，发布前过一遍。

## 7. 已定结论总览

| 维度 | 结论 | 说明 |
|---|---|---|
| 语言定位 | 纯交互方式 | 不是设定、不做解释、不进主线 |
| 世界观包装 | **无** | 删除怀表 / 听潮 / 契约等一切包装 |
| 方向定义 | `zh2en` / `en2zh` | 提示中文→输出英文（角色英语）；提示英文→输出中文（角色中文） |
| 提示语种 | 与输出语言相反 | 玩家看到「想表达什么」的原意 |
| 输出语言 | 与角色当前语言一致 | 判定、语音识别、TTS 都按它 |
| 界面语言 | 独立设置 | 不与提示语种、输出语言合并 |
| 切换时机 | **章末回主界面后** | 章节进行中不可切 |
| 未发送作答 | 禁止切换 | 防止判定方向漂移 |
| 已发送消息 | 不重判、不改写 | —— |
| 进度 | 切换不重置 | 章节、羁绊、SRS、券均保留 |
| 记录 | 句子 + 方向独立 | 双向互不覆盖 |
| 门禁判定 | 按输出语言 | 与 O1 对齐 |

## 8. 仍需用户拍板的岔路口

| 编号 | 岔路口 | 选项 | 方案倾向 | 影响 |
|---|---|---|---|---|
| **C1** | 切换入口位置 | ① 主界面设置 ② 章节结算页 ③ 两处都有 | ① | 影响操作路径与可见性 |
| **C2** | 切换时是否给提示 | ① 一行轻提示 ② 不提示 ③ 二次确认 | ① | 影响误触与理解成本 |
| **C3** | 章节内是否允许「重开本章」换方向 | ① 不允许 ② 允许但清空本章进度 | ① | 与「章节进行中不切换」的边界 |
| **C4** | 双语语义由谁保证 | ① 作者 + 人工校对 ② 允许 AI 直译后不校对 | ① | 影响质量与产能 |
| **C5** | 专有名词策略 | ① 保留原名 + 首现注释 ② 全部意译 ③ 全部音译 | ① | 影响可读性与世界观质感 |
| **C6** | 默认方向与首次选择 | ① 首次进入时让玩家选 ② 默认 `zh2en` | ① | 影响首屏流程 |

建议先定 C1 / C3 / C6，其余可随后定。
