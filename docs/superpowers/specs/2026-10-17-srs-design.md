# SRS 间隔重复 设计规格

日期：2026-10-17
状态：已批准（用户确认到期优先融入主流程、固定阶梯、每日封顶、删除弱项回顾及全部设计节）

## 背景与目标

当前应用只有「弱句加权」：7 天内评过磕绊/不会的句子有 30% 概率被优先抽中，另有「弱项回顾」页提供 30 天弱句列表与手动重练。两者都没有时间调度概念，复习全凭随机与自觉。

本设计引入轻量 SRS（间隔重复）：每句维护熟悉度档位，按固定阶梯安排下次见面时间，抽句时到期句优先。目标是通过科学安排复现节奏提升记忆效率，同时保持应用「随时来一句、不看不欠」的零压力调性——复习不设任务、不弹提醒、每日消化量有上限。

硬约束沿用主规格：纯静态 PWA、无后端、调度状态全部存 localStorage。

## 需求澄清结论

| 决策点 | 结论 |
|--------|------|
| SRS 定位 | 到期优先融入主流程：所有练习会话抽句时先抽到期句，零新入口 |
| 调度算法 | 固定阶梯间隔（6 档），不引入 SM-2/Leitner |
| 积压策略 | 每日封顶：每天最多消化 10 句到期句，超出顺延明天（用户明确不想要复习压力） |
| 弱项回顾页 | 直接删除：tab、路由、视图全下线，SRS 完全无感化 |
| 旧数据兼容 | 历史记录不做推断，所有句子从「未练」开始，练过才入调度 |

## 1. 数据结构与调度规则

新增存储键 `srs.v1`（经现有 storage.js 读写）：

```js
{
  boxes: { [sentenceId]: { box: 1-6, lastTs } },  // 每句调度状态，练过才有
  quota: { date: 'YYYY-MM-DD', used: 0 }          // 今日到期配额计数（本地日期）
}
```

**阶梯**：6 档间隔 `[1, 3, 7, 14, 30, 60]` 天。到期判定：`now ≥ lastTs + 当前档间隔天数`。

**评分映射**（评分落库的同时更新调度状态）：

| 评分 | 档位变化 |
|------|----------|
| 能译 ok | 升一档（第 6 档封顶，保持 60 天间隔） |
| 磕绊 shaky | 降一档（第 1 档不再降） |
| 不会 miss | 回第 1 档 |

新句首次练习直接按上表落档：ok → 第 1 档（明天再见），shaky/miss → 第 1 档。

**粒度**：按 sentenceId 调度，不区分翻译方向（与现有记录、弱句逻辑口径一致）。

**积压策略**：每日到期消化上限 10 句（常量 `DAILY_CAP`，不进设置页）。配额按本地日期计数，跨日自动重置；超期未练的句子不惩罚，照常按队列顺序出队。

## 2. 抽句流程（到期优先融入主流程）

每次抽句的优先级：

1. **到期句**：今日配额未满（used < DAILY_CAP）且到期队列非空 → 出队「最久没练」的那句。队列内顺序出队、不做随机，天然避免反复刷到同一句。
2. **随机句**：无到期句或配额已满 → 沿用现有随机逻辑（排除上一句，防连刷）。

补充规则：

- 四种会话模式（全量/主题/粘贴）走同一逻辑，到期句被会话池子自然限定范围。
- 重练（replay）会话模式随弱项回顾页一起删除，不再是合法会话模式。
- 到期配额只在「抽中到期句且完成评分」时消耗；抽中后未评分（跳过/切句）不消耗。
- 到期句的翻译方向沿用会话当前方向设置，不做特殊处理。

## 4. 测试策略（TDD）

- **srs.test.js（新，核心）**：档位迁移矩阵（三档评分 × 六档边界，含第 1 档不降、第 6 档封顶）；到期计算；配额按本地日期跨日重置；到期队列出队排序（最久没练优先）；冷启动空状态。
- **picker.test.js（改造）**：到期优先命中；配额满退回随机；队列为空走随机；lastId 去重保留。
- **回归**：移除 review.test.js 后现有其余测试保持全绿，加上新增测试总数不低于原有规模。

所有调度逻辑收在 lib 纯函数层，视图层只做接线，可测性优先。

## 5. YAGNI 边界（本次不做）

- 「今日到期 N 句」任何可见入口或角标（SRS 完全无感）
- 复习提醒/推送
- SM-2 等自适应易度系数
- 按翻译方向分开调度
- 到期上限可配置化
- 顺手/撤销评分
