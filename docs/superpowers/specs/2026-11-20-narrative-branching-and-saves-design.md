## 0. 一句话

**一周目不可撤回，选择通过状态累积影响结局；通关后可从关键分支点回溯，旧线保留为只读分支。** 自由度来自「你失去了什么、谁知道真相、谁还愿意帮你」，不来自随机。

## 1. 决议一览

| 编号 | 决议 | 结论 |
|---|---|---|
| N1 | 自由度分层 | L1（骨架）与 L2（关系与信息）都做；L3（台词冷暖）只做即时反应 |
| N2 | 分支形态 | 收束式：主干可合并，真分叉只在关键节点 |
| N3 | 分支保留 | 回溯生成新分支，旧线只读保留 |
| N4 | 结局判定 | 终局结算表，优先级匹配，必须有兜底结局 |
| N5 | 状态可见性 | 隐性可见：不给数值、不给面板 |
| N6 | 写法 | 混合：每章 3–5 处多版本台词，其余用插入句与回指 |
| N7 | 章间传递 | 章内细，章末只导出 2–4 个章级结果 |
| N8 | 沉默 | 不锁死任何结局；额外开放沉默专属结局 |
| N9 | 回溯开放时机 | 首次通关之后 |
| N10 | 回溯性质 | 元层操作，不进故事，角色不知情 |
| N11 | 分支上限 | 软上限 20 条，超出提示清理已完结分支 |
| N12 | 第一版存档 | 自动存 + 岔口书签 + 分支列表；手动槽延后 |

## 2. 三层自由度

| 层 | 改什么 | 成本 | 玩家感知 | 每章预算 |
|---|---|---|---|---|
| L1 骨架 | 走向不同场景 / 不同结局 | 高 | 最强 | 关键分支点 ≤1 |
| L2 状态 | 知道什么、谁信你、谁能帮你 | 中 | 强 | 状态点 3–5 |
| L3 冷暖 | 称呼、态度、后续台词温度 | 低 | 弱 | 不限，即时生效 |

**收束规则**：L1 分叉之后必须能回到主干（汇合点）；只有章末或角色线允许真正不合并的分叉。L3 单独使用不构成自由度，只用于让 L2 被感知。

**成本公式**：成本 ≈ 不可合并的分叉数量，不是选择数量。

## 3. 分支模型

```
branch = {
  id, parentId, forkBeatId,        // 从哪条线的哪个岔口分出来
  status: active | paused | ended,
  endingId,                        // 走到结局才有
  state: { ... },                  // 见 §4
  log: [...],                      // 这条线自己的消息记录
  checkpoints: [...],              // 这条线经过的岔口
  exports: { ... },                // 章末导出，见 §8
  createdAt
}
```

规则：

1. **只有关键分支点产生新分支**。状态点不产生分支，只留在当前分支历史里。否则分支列表会被「我多问了一句」淹没。
2. **回溯 = 新建分支**，父分支原样保留，状态转为 `paused` 或 `ended`。
3. **任意时刻只有一条 active**。切换 active 需要确认。
4. **已到结局的分支只读**，但仍可作为新的回溯起点。
5. **自动命名**：`分支 2 · 23:58 · 电梯厅`。不让玩家起名。
6. **界面只做列表**：按时间倒序，一行一条，显示状态与结局名（未达成显示 `—`）。不做树状图。

## 4. 状态对象

```
state = {
  flags:   { [key]: boolean },      // 剧情事实
  counters:{ [key]: number },       // 少量计数，如 trust 档位
  known:   [clueId],                // 已获得线索
  said:    [candidateId | tag],     // 玩家说过的内容，供回指
  gates:   { [gateId]: pass | read | silent },
  exports: { ... }                  // 章末写入，见 §8
}
```

- `gates` 由门禁系统写入，不参与门禁判定，只参与结算与变体。
- `said` 只记**已发送**的内容，不记草稿、不记未选项。
- 变量总数控制：单章新增 ≤2，全书 ≤8。每章结束清空章内变量，只留 `exports`。

## 5. 结局结算

### 5.1 判定方式

**优先级列表，先命中先定；必须有一条兜底结局。** 不用打分——打分最后没人算得清为什么是这个结局，也无法调试。

```json
"endings": [
  { "id": "echo",  "priority": 1,  "when": { "any": [ { "gates.A": "silent" }, { "gates.B": "silent" } ] } },
  { "id": "shift", "priority": 2,  "when": { "all": [ { "told_back": true }, { "has_roster": true }, { "trust": "high" } ] } },
  { "id": "walk",  "priority": 3,  "when": { "all": [ { "refused_door": "pass" }, { "trust": "high" } ] } },
  { "id": "rain",  "priority": 99, "when": { "all": [] } }
]
```

### 5.2 结算页必须给解释

2–3 行，只讲玩家做过什么与发生了什么，不显示数值：

> 你没有回答那通电话。
> 周砚把手从门把上放下来了。
> 你走的时候，他没有跟出来。

没有这一步，玩家感受不到自由度，会认为结局是随机发的。

### 5.3 第一章（测试章）示例变量

| 变量 | 来源 | 档位 |
|---|---|---|
| `gates.A` | 门禁 A | `pass` / `read` / `silent` |
| `gates.B` | 门禁 B | `pass` / `read` / `silent` |
| `told_back` | 是否把快递单背面的字告诉周砚 | `true` / `false` |
| `trust` | 前两场选择累积 | `low` / `mid` / `high` |
| `has_roster` | 是否拿到值班表线索 | `true` / `false` |

`told_back` 是纯自愿状态点：没有人逼，说了也没有即时奖励。这类点最值钱。

## 6. 隐性可见（N5）

### 6.1 三个出口

1. **称呼**：`Excuse me` → `Hey` → 直接叫名字 → 不再称呼。输出语言为英文时这一层有空间；中文模式不依赖敬称。
2. **行为**：信任高时先一步走到楼梯口；信任低时只抬手指一下方向。
3. **给多少信息**：信任高多说一句没人问过的话；信任低答完就闭嘴。

旁白只写动作，不写「他看起来不太信任你」。

### 6.2 作者纪律

**每个状态变量至少要有两个可感知出口**，写不出来就不要加这个变量。场景卡固定加一行：**本场状态怎么被看见**。写不出这一行，这场戏没写完。

### 6.3 验证法（不用代码）

找人玩完问一句：「你觉得周砚最后信你吗？为什么？」说得出具体依据即成立；只能说「不知道」即失效，回去补出口。

### 6.4 禁止

- UI 上提示「信任 +1」或任何数值变化。
- 用 toast / 角标提示状态变动。
- 在结算页之外解释机制。

## 7. 写作形式与预算（N6）

| 形式 | 每章数量 | 用在哪 |
|---|---|---|
| 多版本台词 | 3–5 处 | 关系不可逆地变了一点的那一句 |
| 条件插入句 | 每场 1–2 句 | NPC 即时反应、旁白动作细节 |
| 回指 | 1–2 处 | NPC 提起玩家上一场说过的话 |

### 7.1 多版本的准入判据

满足任意一条才配多版本：① 这句是关系转折的锚点；② 玩家事后会记住它；③ 不同说法会改变下一场的行为，而不只是语气。三条都不满足，写一版，用插入句解决。

### 7.2 回指三条规则

1. 只引用已发送的内容。
2. 引用说法与态度，不引用语言错误（不嘲笑语法、口音）。
3. 回指必须推进当前处境，不能只是炫技。

第一章最有效的一处回指：第三场门内声音复述「你刚才跟他说，这里没有陈迟」——玩家的谎被第三方复述。

### 7.3 数据形态

```json
{
  "id": "ch01_s3_07",
  "kind": "npc",
  "speaker": "door_voice",
  "variants": [
    { "when": { "gates.A": "pass" }, "text": { "en": "You told him there was no one here.", "zh": "你刚才跟他说，这里没有陈迟。" } },
    { "when": { "gates.A": "read" }, "text": { "en": "You read it off a screen, didn't you.", "zh": "那句话你是照着念的，对吧。" } }
  ],
  "default": { "text": { "en": "You didn't answer the phone.", "zh": "那通电话你没接。" } }
}
```

插入句用 `when` 挂独立 beat，命中才出现，不命中直接跳过、不占位。变体冲突时按顺序取第一条，必须写 `default`。

## 8. 章级交接（N7）

### 8.1 规则

- 每章只导出 **2–4 个**，类型只有布尔与枚举，不收数字。
- 词表全局、封闭；下一章只能读清单词，读不到章内变量。
- **由结局声明导出值**，不从原始状态反推。

```json
{ "id": "shift", "exports": { "knows_truth": "full", "zhou_yan": "with_you", "told_back": true } }
```

### 8.2 三条校验

1. 后续章节不得引用章内变量。
2. 每个清单词的每个取值都必须有可玩内容；不允许「某个值 = 后面没内容」。
3. 清单词发布后不改名，只加新词。

### 8.3 与分支的关系

`exports` 跟着**分支**走，不跟全局走。同一条线重走第一章，新分支带自己的 exports，老分支保留原来的。只有结局图鉴是全局的。

```
branch.state.exports = { knows_truth: "full", zhou_yan: "with_you" }
meta.endingsSeen     = [rain, echo]      // 全局，永不被回溯抹掉
```

## 9. 沉默政策（N8）

| 结果 | 玩家做了什么 | 剧情里发生什么 | 结算档位 |
|---|---|---|---|
| 说出口 | 自己组织语言，信息槽到位 | 对方听见了 | `pass` |
| 照读 | 点 R3 参考译文照念 | 话说出去了，但不是你的话 | `read` |
| 沉默 | 显式选择「不说话」 | 话没说，世界照样往前走 | `silent` |

规则：

1. 沉默是**显式选项**，不是关掉游戏或不操作。不弹失败、不重试、不卡住。
2. 沉默**不锁死任何结局**，只降低结算权重、改变后续可选项。
3. 沉默**额外开放**一个专属结局（例：「回声」——你从头到尾没开口，门学会了你的声音）。专属结局只对沉默开放，不妨碍其他结局可达。
4. 限时沉默（O4 v3 §8）到点等于没把话说出口，共用同一 `silent` 档位。

## 10. 存档与元进度

### 10.1 存储划分

| key | 内容 | 回溯时 |
|---|---|---|
| `story.ch01.branches.v1` | 分支数组 + activeId | 保留全部 |
| `story.meta.v1` | 结局图鉴、线索图鉴、关系记录 | **永不清空** |

`resetStoryState()` 只清 active 分支，不清元进度。

### 10.2 存档点

- **每条消息边界自动存**（现有行为保留）。
- **每个关键分支点自动写书签**，不依赖玩家手动存。
- **回溯只在首次通关后开放**。第一次玩时「可以反悔」的念头一旦存在，选择就会变轻。
- 分支列表只显示**已访问节点**，未到过的地方留空位。

### 10.3 回溯流程

```
首次通关 → 结算页出现「回溯」
        → 分支/岔口列表（只含已访问）
        → 选中岔口 → 显示当时时间、地点、状态摘要
        → 确认（提示：该节点之后的当前进度将丢弃）
        → 新建分支，从岔口继续
        → 走到新结局 → 结局图鉴 +1
```

### 10.4 张力处理

- **不可撤回**作用于这一遍：发送即定，不能编辑、不能撤销、不能逐句回退。
- **可重来**作用于这一遍之外：从岔口新建分支，丢弃之后的进度。
- **知识保留、处境重来**：结局图鉴与线索卡跨分支保留，剧情状态退回。

## 12. 校验规则

1. 每个结局至少有一条路径可达（枚举分支组合，不靠人肉推）。
2. 没有死节点：任何状态都能落到某个结局，包括全程沉默。
3. 必须有兜底结局。
4. 同一位置的 `when` 不得有两条同时命中。
5. 每个状态变量的每个档位至少被一条 `when` 引用，否则是死变量。
6. 后续章节不引用章内变量。
7. 每个 export 词、每个取值都有可玩内容。
8. 硬门禁数量与位置仍受 O1 约束，不因分支增加。
