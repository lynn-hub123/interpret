### 0.1 术语

| 术语 | 含义 |
|---|---|
| 软门禁 | 翻译不完美也可以发出去，后果体现在 NPC 反应、关系、线索、结局 |
| 硬门禁 | 不通过就发不出去，必须重译、看提示或走出口 |
| 门禁句 | 被标记为硬门禁的那一句发言 |
| 关键 beat | 允许出现硬门禁的叙事节点 |
| 信息槽 | 一条台词必须传达的最小语义单元（谁、做了什么、时间、否定、数量） |
| 风味层 | 不决定通过，只改变 NPC 反应与后续台词冷暖的表达维度 |

现状一句话：**它是"口译练习器 + 叙事皮肤 + 收集层"，不是 RPG。**

### 1.1 三个必须记住的修正

1. **主线实际两幕，不是四幕。** 四个场景文件里只有两个被加载；"走完全部主线"就是两幕。
2. **现有布局是竖屏单列，不是横屏。** 真正的结构冲突是"单卡单页"和"连续聊天流"，不是屏幕方向翻转。
3. **羁绊是死数值。** 它现在是纯展示，正好可以在新设想里改造成关系值。

### 1.2 缺失的 RPG 骨骼

玩家属性、等级/经验、地图探索、对抗系统、资源经济、NPC 关系网、失败状态——现在一个都没有。现有 RPG 元素集中在**叙事包装 + 抽卡奖励**。

## 2. 新定位（已确认）

一句话：**竖屏、聊天流、对话驱动的叙事游戏；翻译不是练习环节，而是角色开口说话的方式。**

### 2.1 叙事形式

- 竖屏，聊天软件式界面，参考《生命线》《幽灵事务所》。
- 其他角色用头像 + 对话框；玩家是"主控"，以聊天方式回复。
- 现代悬疑恐怖为基底，混入奇幻：角色可以是人、非人、人型、非人型。
- 全性向：关系线不锁玩家性别与取向。

### 2.2 核心交互回路

```
收到 NPC 消息
  → 读懂
  → 看到自己"要说的话"（待翻译的原意）
  → 录音或打字译成目标语言
  → 发送
  → NPC 回应 / 剧情推进
```

- 中英模式随时切：中文模式下你中译英，NPC 说英文；反之亦然。
- 关键点：翻译不是"练完给反馈"，而是**发送按钮本身**。不译，就说不出话。

### 2.3 内容结构

- 主线：现代悬疑恐怖，多幕。
- 角色线：抽卡获得角色 → 独立剧情 → 选择 → 多结局 → 关系状态 + CG。
- 角色形态多样：人、非人、人型、非人型。
- 全性向关系。

### 2.4 成长与收集

- 抽卡（后期加入）、角色卡、独立剧情、结局、CG、关系。
- 现有券、稀有度、保底、剪影、隐藏形态可作为素材，但语义要重定。

### 2.5 表现与平台

- 竖屏、聊天流主界面、头像 + 气泡、CG、恐怖氛围。
- 纯静态 PWA、localStorage、无后端（现有硬约束）。
- 双语内容 + 音频，这是最大的隐形成本。

### 2.6 三条语义约定（工作理解）

以下三条按当前理解推进；若与实际设想不符，归入对应未决项一并修正。

1. **中文模式** = 你从中文翻到英文，NPC 说英文，你看到的待发内容是中文原意；英文模式反之。（细节归 O3）
2. **全性向** = 任意玩家性别/取向都能走任意角色线。（落实方式归 O6）
3. **抽卡后期加入** = 第一版主线不含抽卡，抽卡属于第二阶段。（阶段划分归 O5）

## 3. 与上一轮四种方向的关系（已确认）

上一轮四个候选方向：

- **A. 叙事探索型**：重心在走场景、对话、找线索、做抉择；练习是关卡门禁。
- **B. 练习核心 + RPG 动机层**：练习是主体，RPG 负责成长曲线、解锁、叙事奖励。
- **C. 系统经营型**：角色养成、资源分配、对抗；练习是生产动作。
- **D. 只加内容，不改结构**：扩场景、角色、支线，架构不动。

### 3.1 它最接近 A，但其实是第五种

- **最接近 A**：重心在故事、角色、抉择。
- **但不是 A**：A 的"走动、地图、找线索"被替换成"对话、关系、回消息"。更准确的说法是 **E. 对话驱动的叙事游戏**。
- **与 B 的关系**：B 说"练习是主体，RPG 是动机层"；这套设想把练习变成**叙事动作**——主体是故事，但玩家唯一的动词是翻译。所以它是 **A 的重心 + B 的强制动作**。
- **与 C 无关**：没有属性加点、资源经营、战斗数值；成长是关系与收集，不是 build。
- **偏离 A 的地方**：没有空间探索、没有对抗系统、没有角色属性。它更接近互动小说/视觉小说，而不是系统驱动的 RPG。

### 3.2 一句话

**不是"RPG 包住练习"，是"练习就是角色说话的方式"。** 这是这套设想最强的一点，也是它和现状最根本的分歧。

## 5. 双档门禁（已确认）

### 5.1 基本结构

- **常规消息走软门禁**：可以发出去，NPC 察觉不完整，代价体现在关系、线索、结局。
- **关键节点走硬门禁**：不通过就发不出去。

### 5.2 门禁落在"说"，不落在"选"

玩家永远可以先选立场，再执行这句话；失败改变的是"这句话怎么落地"，不是"你有没有资格选这个分支"。

- 不把门禁放在"分支选项能否被选择"上：否则语言能力会直接锁剧情分支，和"全性向、多结局、关系自由"的承诺冲突。
- 门禁放在"发言执行"上：玩家选了立场之后，必须能把这句话说出来；说不出来，故事仍然继续，只是落点不同。

### 5.3 单位：节点层定类型，发言层定门禁

- **节点层**决定这个 beat 是不是关键 beat（允许出现硬门禁）。
- **发言层**决定这个 beat 里哪一句是门禁；其余句子仍是软门禁。
- 一个关键 beat 里可以只有一句硬门禁；一个普通 beat 里也可以有一句"说了就生效"的关键台词。

**为什么不建议节点级全硬门禁**：整段变成考试，疲劳且通胀。
**为什么不建议选项级门禁**：语言能力锁分支，玩家会觉得"游戏替我选了故事"。

## 6. 五类关键清单、预算与前置信号（工作规则）

### 6.1 五类关键

只有落在以下五类里的发言，才允许做硬门禁：

1. **真相揭露**：这句话一说，某件不可逆的事实就成立了。
2. **生死**：说错或说不出，直接改变某人的生死。
3. **关系转折**：这句话定义了一段关系的性质（告白、决裂、背叛、原谅）。
4. **不可撤回的承诺或仪式**：说了就生效（誓言、契约、咒语、名字）。
5. **语言本身就是行动**：警告、撒谎、命令、求饶——内容对，效果才对。

不落在这五类里的，一律软门禁。

### 6.2 反通胀规则

- **预算**：每章 2–3 个硬门禁（初始默认，可调）。
- **缓冲**：两个硬门禁之间至少隔一个软场景。
- **前置信号**：玩家输入前就要知道"这句话收不回"；信号必须叙事化（对方停顿、输入框变化、环境音消失），不是红色警告。
- **事后不惩罚**：不能等玩家失败后才告诉他这是硬门禁。

### 6.3 对剧本数据与制作流程的含义

剧本数据需要能表达五件事：

1. 这个 beat 是不是关键 beat。
2. 这个 beat 里哪一句是门禁句。
3. 门禁句属于五类里的哪一类。
4. 通过标准与提示阶梯是什么。
5. 失败后果是什么（关系、线索、后续台词）。

制作流程随之变化：

- 编剧产出一张"门禁表"：beat、门禁句、功能类别、通过标准、提示阶梯、失败后果。
- 编辑校验：功能必须在五类内；每章预算；每条门禁句必须有本地可判定的语义核心。
- QA 跑"门禁矩阵"：离线/在线、语音/打字、通过/失败/放弃，逐条过。

## 7. 离线判定六条立场（已确认）

纯静态、无后端是硬约束。立场一句话：

**本地优先、AI 可选、自评兜底、硬门禁失败时降级为软门禁，绝不让玩家卡死。**

1. **打字永远是硬门禁的合法路径。** 语音是增强，不是门槛；Web Speech 识别经常依赖联网和浏览器支持，不能当地板。
2. **每条硬门禁句必须"本地可判定"。** 作者提供语义核心（必须传达的信息槽），加 2–3 种可接受说法，加不可接受的逆转（否定反了、主语错了、时态错了）。不能本地判定的句子，不许做硬门禁。
3. **AI 是放大器，不是门神。** 有 key 且在线时，它接受更多合法意译、给更细的反馈；没有时，本地判定照跑。
4. **本地判不了 → 自评承诺。** 玩家确认"我说到了/我没说到"，界面明确标注"本次为自评"。
5. **所有判定路径都不可用 → 硬门禁降级为软门禁。** 消息发出去，故事记下"你说得不够清楚"，继续。游戏永远可通。
6. **降级必须告知。** 玩家要知道这一关是真判还是降级判，否则通过和失败都没有意义。

**必须一起接受的代价**：本地判定天然擅长"信息是否到位"，不擅长"语气是否成立"。所以通过标准不能脱离这条约束单独选（见 §8）。

## 8. 通过标准（已确认）

### 8.1 底线：信息到位

只要关键信息传达到，就算过。信息槽至少包括：

- 谁
- 做了什么
- 时间
- 否定关系
- 数量

允许磕绊、语法瑕疵、口音、非母语语序。这既符合口译"意义传递"的本质，也最适合离线本地判定。

### 8.2 风味层：语气成立

- 语气不决定过不过。
- 语气改变 NPC 的反应、关系的走向、后续台词的冷暖。
- 它是"软门禁 + 关系系统"的输入，不是"硬门禁"的判定项。

### 8.3 分工

- **硬门禁判信息**：过不过，看信息槽。
- **软门禁判语气与关系**：这句话说得体不体面，落在关系、线索、后续台词上。
- **离线可行性**：底线可本地判定；风味层可离线降级为自评，或在线时由 AI 增强。

## 9. 安全阀原则（建议，具体形态待定）

硬门禁是压力峰值，必须有安全阀。以下原则已提出，具体形态归 O1。

- **前置信号**：输入前就知道这句话重要。
- **重试阶梯**：第一次给具体但不完整的提示；第二次给结构提示；第三次给完整参考或出口；不重复同一句失败文案。
- **出口永远存在且叙事化**："说不出口/沉默"是合法动作，故事继续，代价落在关系或线索上。
- **失败改变路径，不结束游戏**：语言失败不 game over，除非是明确可重试的死亡节点。
- **默认无倒计时**：恐怖来自内容，不来自计时。
- **缓冲**：硬门禁之后给一个软场景，不连续堆叠两个硬门禁。
- **无障碍**：打字、重听、可调字号、不强制语音。
