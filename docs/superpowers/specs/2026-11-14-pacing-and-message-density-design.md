## 0. 一句话

**故事优先于密度。** 推荐即时回复为默认、停顿由作者逐条编排、不做真实倒计时；玩家发言默认都要用目标语言译出，NPC 与旁白只读。消息条数与读写比例不作为写作配额，只在写完后用于体检场景是否失衡；唯一底线是每章至少有一两处「不译就真的过不去」的时刻。**默认不限时**，只有极少数冲突/恐怖/紧迫场景可使用「限时沉默」（§8），且不作为失败重试。

---

## 1. 问题拆解

| 子问题 | 决策点 | 影响 |
|---|---|---|
| 回复时序 | 即时 / 固定延迟 / 作者编排 | 恐怖节奏与等待焦虑 |
| 会话长度 | 一次坐下能玩到哪、在哪存档 | 移动端留存与断点体验 |
| 必译范围 | 哪些消息触发玩家翻译 | 练习负荷与「聊天流变练习册」的风险 |
| 消息密度 | 每场戏的疏密、单条多长 | 阅读疲劳与场景呼吸 |
| 恐怖节拍 | 何时停顿、何时推进 | 压迫感是否成立 |
| 人设 | NPC 是否有自己的目的与记忆 | 对话是否值得发生 |

核心矛盾：**翻译是发言动作**，但每条消息都要译会把聊天流变成刷题；反之只读太多又练不到。O4 不提供写作配额，只提供判断失衡的体检线与一条底线。

---

## 2. 消息分类与必译规则

| 类型 | 示例 | 是否必须译 | 说明 |
|---|---|---|---|
| 旁白 / 环境 | 「楼道里的灯闪了一下。」 | 否 | 只读，自动推进 |
| NPC 台词 | 「你刚才听见了吗？」 | 否 | 只读；可触发玩家回合 |
| 玩家回合 | 玩家要回一句话 | **是**（短回复免译是可选设置，默认关） | 必须用输出语言发送，含软/硬门禁 |
| 系统提示 | 「录音中」「识别失败」 | 否 | 只读 |
| 可选项 | 重听、查词、回看 | 否 | 不计入练习量 |
| 已发送消息 | 玩家自己发过的话 | 否 | 不重译、不改写 |

规则：

1. 玩家发言默认都必须译，包括一句短回应。设置里提供「短回复免译」开关，**默认关闭**——口子开着，人容易一路滑过去，把对话练成点选；开关只作用于**非门禁回合的短回复**，硬门禁不受影响。
2. NPC 与旁白默认只读；只有被标记为「玩家回合」的消息才要求输入。
3. 硬门禁是玩家回合的子集，不是独立消息类型。
4. 不设「连续只读最多几条」的硬规则；如果一场戏长时间没有轮到玩家，按 §4 的体检线检查它是否变成了看小说。
5. 已发送消息不回炉；R3 照读同样是一次玩家回合。

## 3. 回复时序

### 3.1 默认：即时

- NPC 回复默认 **≤0.4 秒**出现，或极短「正在输入」0.4–1.2 秒后出现。
- 默认不做真实倒计时、不做限时选择、不做「几秒内不回复就失败」；限时沉默是唯一例外（§8）。
- 玩家可以无限思考；输入框一直可用。

### 3.2 作者编排的停顿

- 每条 NPC 消息可标 `delay`（秒），默认 0；常用 1.5–4 秒。
- 停顿期间显示「正在输入」；推荐上限 8 秒（D2 待定），超过按上限处理。
- 停顿用于恐怖或情绪节拍，不用于普通信息传递。
- 停顿可被玩家点击跳过；跳过不改变结果。

### 3.3 不用实时机制

- 默认不用「已过 X 分钟」「倒计时」「实时语音通话」；限时沉默是唯一例外，见 §8。
- 「已读不回」可以作为恐怖节拍：NPC 不回复、输入中消失；但玩家始终可以继续操作或退出。
- 断网、切后台、锁屏后回来，消息按已到达状态恢复，不追补延迟。

## 4. 密度：由场景功能决定，写完后体检

### 4.1 写作时不受条数约束

- **不设「每场多少条、每章多少条」的写作配额。**
- 密度由场景功能决定：
  - 逼问、争吵、追逐、倒计时：可以密集、短句、快速来回。
  - 沉默、等待、独处、观察：可以稀疏，允许长段只读与停顿。
  - 同一章的不同场景应当有不同的呼吸，不追求统一节奏。
- 一场戏需要多少条消息，取决于它要制造什么感受；先写出来，再判断。

### 4.2 事后体检线（参考，不是规则）

写完后拿以下问题检查，而不是拿数字卡写作：

| 体检项 | 参考区间（经验值，非标准） | 失衡信号 |
|---|---|---|
| 单场消息数 | 6–18 条 | 少到场景立不住，或多到读不完 |
| 单场玩家回合 | 1–6 个 | 连续点按像刷题，或整场插不上话 |
| 连续只读 | 5 条以上就该检查 | 玩家长时间没有参与感 |
| 场景节奏 | 至少两种节奏 | 全场同一速度，没有起伏 |
| 单条长度 | 竖屏 3 行内 | 气泡过长，手机上读不完 |
| 硬门禁 | 见 §5 | 为凑数加门禁，或全场没有非译不可 |

这些数字只用于**事后判断是否失衡**，不作为写作目标，也不作为验收硬指标。真正要守的是「这场戏有没有该有的呼吸」。

### 4.3 不设读写配比

- 不规定「每几条消息必须有一次发言」。
- 判断标准是体感：玩家如果一直在点，或长时间插不上话，就是失衡；**改戏，而不是套比例**。

---

## 5. 硬门禁的底线（不是配额）

- 硬门禁数量**由剧情节点决定，不凑数**，不设「每章必须几个」的指标。
- O1 的「每章 2–3 个」是**上限**，不是任务量；可以少于上限。
- **底线：每章至少应有一两处「不译就真的过不去」的时刻。** 它不是配额，而是下限，用来防止翻译退化成可跳过的附属动作。
- 如果一章写完发现没有任何一处非说不可，说明章节功能有问题：应当改剧情、改关系压力，而不是临时加门禁。
- 硬门禁不限时；限时沉默不叠加在硬门禁上。
- 硬门禁应落在真正有代价的节点：真相、生死、关系转折、不可撤回的承诺、语言即行动。

---

## 6. 会话长度与断点

- 不设硬性时长；一个场景通常能在一次坐下内完成，具体由场景功能决定。
- 每条消息边界都可存档；退出不惩罚、不丢进度。
- 场景结束给明确结算：本场内容、门禁结果、下一场入口。
- 章末才允许切换语言方向（见 O3）；场景中途不切。
- 不做「每日体力 / 每日任务」类回流压力。

---

## 7. 恐怖节奏曲线

每个场景一条小曲线，每章一条大曲线（形态参考，不是模板）：

```
平静 → 异样 → 峰值 → 释放
```

- **平静**：建立空间与声音，长度由场景决定。
- **异样**：出现异常，可配停顿。
- **峰值**：本场的硬门禁，或 H3 场景的氛围峰值（H3 不叠加硬门禁）。
- **释放**：短消息 + 场景切换，让玩家喘口气。
- 通常避免把两个峰值紧挨在一起，但以戏为准；不是硬规则。
- 不是每场都必须有硬门禁；没有门禁的场景可以用氛围峰值承担压力。

## 8. 限时回应（timed response，少数例外）

### 8.1 术语与形态

- 参照两类既有设计：**QTE（Quick Time Event）** 与 **timed dialogue choice**（限时对话选择）。
- 但**本作不做按键 QTE**：玩家正在打字或录音，手被占用，按键反应既不公平也不像对话。
- 本作形态是**限时沉默**：倒计时到点，视为玩家**没有把这句话说出口**。
- 结果不是「失败 / 重试」，而是让叙事继续：
  - NPC 接话或替玩家把话说完；
  - 局面自行推进（对方离开、门关上、灯灭、车开走）；
  - 玩家的角色咽下这句话，用一句内心旁白收束。
- 不弹「挑战失败」，不出现重试按钮，不把超时计入失败次数。

### 8.2 规则边界（写死，防止后续滥用）

1. **默认全局不限时**；只有数据里显式标注 `timed` 的玩家回合才计时。
2. 仅用于**冲突、恐怖、紧迫**类场景；每章一两次，是叙事选择，不是配额。
3. **不叠加硬门禁**：硬门禁不限时；限时回合不判信息槽，只看玩家是否把话说出口。
4. 时限按文本长度给足：以「读完提示 + 组织语言 + 开口」为准。初始参考值：短句 20 秒、长句 30–45 秒，按字数递增；具体数值可调。
5. 到点后输入区收起，未发送的草稿**不保留**（默认；是否保留可另行定）。
6. 设置内提供**总开关**；关闭后所有 `timed` 节点恢复为不限时，流程不变。
7. 无障碍：可随时关闭；不用于强制教学；超时不结束剧情、不扣券、不扣关系数值（推荐，见 D8）；不进入失败统计。
8. 以下场景**禁止**使用限时：硬门禁、关键教学句、切换语言后的首句、玩家开启无障碍/关闭限时的状态。

### 8.3 与「不做倒计时」原则的关系

- 默认原则不变：**绝大多数回合不限时，玩家可以无限思考**。
- 限时是「来不及了」的叙事例外，只能由数据逐条标注，不能写进通用流程。
- 没有 `timed` 标注就没有计时；除设置总开关外，不提供「全局限时模式」。
- 限时只影响「话说没说出口」，不影响判定难度；打字与录音同权，不奖励手速。

### 8.4 呈现形态

- 输入区上方显示细进度条或沙漏，不显示刺眼的大数字倒计时。
- 最后 5 秒可有轻微脉冲；动效可被「减少动态」设置关闭。
- 到点：输入区收起 → NPC 接话/旁白推进 → 进入下一回合；无失败音效。
- 玩家已发送的消息不受影响；限时只作用于当前未发送的回合。

### 8.5 与其它模块的关系

- **O1 硬门禁**：硬门禁不限时；限时回合不是硬门禁，也不进入五类关键节点。
- **O2 内容尺度**：H3 场景可以使用限时沉默，但 H3 仍不设硬门禁；限时不作为恐怖强度分级。
- **O3 语言切换**：场景内输出语言固定，限时不改变语言与方向。
- **§4 密度**：限时场景通常更密集，但仍按体检线检查，不因限时免检。

### 8.6 推荐

- 默认开启，但只作用于被标注的少数节点；关闭开关后完全恢复不限时。
- 超时视为「没说出口」，不判错、不重试、不扣券；剧情用 NPC 接话或旁白继续。
- 每章最多一两次，优先放在「对方即将离开 / 门正在关上 / 灯即将熄灭」这类不可逆瞬间。

## 9. 人设与代入感

角色值得对话，不是因为立绘或标签，而是因为**他非听你说不可**。以下是可操作的抓手，不是性格清单。

### 9.1 NPC 有自己的目的

- 每场戏写清：**他这场想从玩家这里得到什么**（信息、承诺、妥协、沉默、离开）。
- 即使玩家不开口，NPC 也会推进自己的目标：催促、施压、转移话题、直接行动。
- NPC 不是等待输入的反应器；玩家沉默时，世界仍然在动。

### 9.2 NPC 记得玩家怎么说过

- 记录玩家上一场/上一章的表达痕迹：用过的说法、回避的问题、语气、承诺。
- 下一场让 NPC 回指： 「你上次说『也许』。你总是留后路。」
- 只引用**已发送**的内容；不引用未发送的草稿。
- 回指的是**说法与态度**，不是语言错误；NPC 不嘲笑玩家的语法或口音。

### 9.3 反应有延迟与情绪残留

- NPC 可以不立即回应：沉默、已读不回、下一场才提。
- 上一场的冲突会改变这一场的称呼、距离、是否愿意帮忙。
- 情绪有残留与衰减，不因换场景清零；也不要求每场都解释。

### 9.4 「非听你说不可」要有具体理由

- 每个关键 NPC 至少有一条可验证的理由：只有玩家能翻译、只有玩家知道某件事、契约/时限/身份限制。
- 理由要落在剧情事实里，不写成「剧情需要」。
- 当理由消失时，关系应发生变化；不能永远需要玩家。

### 9.5 每场戏的三个抓手

写一场戏前，先写三行：

1. **他想要什么**（本场目标）。
2. **玩家上次留下了什么**（一句可回指的话或态度）。
3. **他为什么现在非听玩家说不可**（具体理由）。

三行写不出来，这场戏大概还不成立。

### 9.6 反模式

- 用性格标签代替行为：写「冷漠」，却没写他冷漠时具体做什么。
- NPC 只负责抛出台词等玩家回答，没有自己的行动线。
- 玩家说什么都一样，NPC 没有记忆、没有情绪残留。
- 需要玩家的理由永远是「你是主角」。

### 9.7 对实现的含义（不含代码）

- 需要记录玩家的「表达痕迹」：用过的关键词、回避、承诺、语气倾向；只用于回指，不用于评分。
- 需要按剧情 flag 触发回指台词，而不是每场重新认识玩家。
- 情绪状态可以轻量承载（如 `mood` / `trust` 的定性档），不要求复杂数值系统。

## 10. 竖屏呈现规则

1. 一条消息一个气泡；单条控制在 3 行内，长文本按语义拆条（可读性约束，不是写作配额）。
2. 玩家在底部时自动滚动；玩家上滑回看时停止自动滚动，显示「新消息」按钮。
3. 「正在输入」按 §3.2 的上限显示；消失即视为该条消息结束。
4. 玩家消息与 NPC 消息左右分栏；玩家消息附带「原意」折叠入口（发送后才可看）。
5. 输入区固定底部：文字输入、录音、发送；录音中显示计时与识别文字。
6. 语音默认点击播放；关键台词可自动播放（D4），并提供全局静音。
7. 不做未读红点、不做消息条数压力显示。

---

## 11. 与其它模块的关系

- **O1 硬门禁**：2–3 个/章是上限，不是指标；重试阶梯与停顿互不影响。
- **O2 内容尺度**：H3 场景不设硬门禁，峰值改用氛围与停顿。
- **O3 语言切换**：章末才可切换；单场景内输出语言固定。
- **O5 抽卡**：第一版切片不含抽卡。
- **O9 SRS**：复习句可插在场景之间，不插在峰值中间。

## 12. 推荐总览

| 维度 | 推荐 | 说明 |
|---|---|---|
| 优先级 | 故事优先 | 密度数字只做事后体检 |
| 回复时序 | 即时 + 作者编排停顿 | 默认 ≤1.2 秒 |
| 真实倒计时 | 默认不做 | 保持练习低压力 |
| 限时沉默 | 少数节点，可关闭 | 仅冲突/恐怖/紧迫，每章一两次（§8） |
| 必译范围 | 玩家回合默认都译 | 短回复免译为设置项，默认关（D3 已决） |
| 密度 | 由场景功能决定 | 不同场景不同呼吸 |
| 硬门禁 | 数量由剧情节点决定 | 底线：每章一两处非译不可 |
| 存档 | 每条消息边界 | 退出无惩罚 |
| 语言切换 | 章末 | 与 O3 一致 |
| 人设 | 目的 + 记忆 + 延迟 + 理由 | 见 §9 |

## 13. 仍需用户拍板的岔路口

| 编号 | 岔路口 | 选项 | 方案倾向 | 影响 |
|---|---|---|---|---|
| **D1** | 回复时序 | ① 全即时 ② 固定短延迟 ③ 作者逐条编排 | ③（默认即时） | 恐怖节奏与实现复杂度 |
| **D2** | 停顿编排与上限 | ① 4 秒 ② 8 秒 ③ 不限 | ② | 压迫感 vs 等待焦虑 |
| **D3** | 短回复是否免译 | **已决：提供设置项，默认关闭；只作用于非门禁回合的短回复，硬门禁不受影响** | 默认关：口子开着容易一路滑过去 | 核心机制纯度 vs 操作流畅 |
| **D4** | NPC 语音 | ① 点击播放 ② 关键句自动播放 | ②（可静音） | 氛围 vs 打扰 |
| **D5** | 是否提供「只看剧情」模式 | ① 不提供 ② 提供（无判定） | ① | 会绕过核心练习 |
| **D6** | 限时是否计入练习记录 | ① 不计入 ② 计入但标注「未说出口」 | ① | 记录纯度 vs 数据完整 |
| **D7** | 超时后是否允许补一句 | ① 不允许，叙事继续 ② 下一回合可补 | ① | 「来不及」的分量 |
| **D8** | 超时是否影响关系数值 | ① 不扣数值，仅落剧情 flag ② 扣少量 | ① | 压力 vs 挫败感 |
| **D9** | 限时开关默认 | ① 默认开 ② 默认关 | ① | 体验完整 vs 无障碍优先 |

D3 已决；建议接着定 D1 / D2；D4、D5 可随后定；D6–D9 随限时方案一起定。

## 附录：最小可玩竖切片（示例规模）

用于判断「要不要先做这一版」。**以下数字是为估算工作量给的示例规模，不是标准、不是配额，也不是正式排期。**

| 项 | 示例规模 |
|---|---|
| 章 | 1 章，3 个场景（抵达 → 异常 → 对峙） |
| 时长 | 约 30–40 分钟，可拆 2–3 次玩完 |
| 玩家回合 | 约 10–12 个，默认全部需译 |
| 硬门禁 | 示例 2 个，分置场景 2 与场景 3（不是每章必须 2 个） |
| 句子量 | 约 12 条原意 + 12 条参考译文；另 20–24 条只读旁白/NPC 台词 |
| 美术最小集 | 1 张场景背景、1 个角色头像/半身、1 张 C1 插画、现有像素壳与输入/录音控件 |
| 文本最小集 | 3 个场景脚本、2 个门禁配置、1 份内容提示、1 份结算页文案 |
| 音频最小集 | 6–8 条关键 NPC 台词（中英各一套），其余静音 |
| 系统最小集 | 聊天流、输入/录音/发送、本地判定、存档、章末结算；不做抽卡、图鉴、SRS 面板 |

**最容易出问题的两处**

1. **判定与提示粒度**：太松会「随便说说就过」，太严会卡死；切片必须验证「三次重试 + R3 照读」这条链真的能走通，且不泄露答案。
2. **节奏被练习打断**：每个回合都要译，容易变成「做题 + 看剧情」两张皮；切片要验证聊天流是否仍然像聊天，而不是练习册。
