# 聊天流 UI 基线（2026-11-15 定稿）

状态：**生效**，替代 `2026-11-14-pixel-style-baseline.md`｜日期：2026-11-15
适用：竖屏聊天流「对话驱动 RPG」全部新界面——聊天、场景、门禁、设置、结算

---

## 0. 一句话

暗紫黑打底，冷紫白只做光，玫红只做一笔。界面靠构件与留白立住，不靠描边，也不靠说明文字。

---

## 1. 色彩

**V1 · 底色阶**　所有大面积底色只能落在 `#08070E`–`#2B2A3A` 之间。背景、面板、抽屉、气泡都取这个区间，不得引入区间外的灰、蓝、绿。

**V2 · 唯一高光**　冷紫白（`#DCD6EC`–`#F2EFFB`）是全局唯一高光色，只用于门缝、灯光、焦点框与最高层级文字。一个画面里发光的地方不超过两处。

**V3 · 玫红点睛**　`#9A4E68` / `#C08FA2`，饱和度上限 45%，只做 1–2px 线与虚线框、图标点色。**不铺面、不做正文色、不做按钮底。**

**V4 · 金属**　暗镍取代黄铜；冷褐与锈红只作少数材质色（门框、管道、旧金属），不进入 UI 主体配色。

**V5 · 明度顺序**　墙 < 地面 < 门 < 光，从暗到亮。任何场景分层不得倒置；倒置会让「光」失去意义。

---

## 2. 字体

**V6 · 中文正文**　清晰无衬线，17px / 行高 26。正文不参与任何装饰性处理。

**V7 · 像素字**　像素字只保留在时间戳、场景标题、两个词以内的短标签（如「线索」「完」）与数字 / 倒计时上，字号只取 24 / 36 / 48 三档。**英文正文、英文台词与参考译文改用中文正文同一套无衬线，17px / 行高 26**。修订原因：长英文段落用像素字时字面窄、一句话占三行，阅读成本过高（2026-11-15 修订）。

**V8 · 中英混排**　baseline 对齐；同一行内不混用两种行高。像素字与正文混排时行高统一 16（12 底模的 1.33 倍），正文之间统一 26。

**V9 · 字体落地**　当前使用系统字体栈，**不保证跨端一致**；跨端统一前必须自托管子集（中文子集 + 像素字 woff2），不得依赖 CDN。

---

## 3. 网格与形状

**V10 · 盒模型**　尺寸与位移走 4px 网格；描边固定 1px。

**V11 · 正文例外**　黑体正文可自由缩放，不落 4 网格（17px 即为例外）；受 4px 约束的只有盒模型与构件尺寸。

**V12 · 形状**　全直角，无圆角，无软阴影，无模糊光晕。

**V13 · 动效**　过渡按帧跳，不用平滑缓动；转场用位移推，不用淡入淡出。只允许对透明度与位移做阶跃，禁止对尺寸与颜色做插值。`prefers-reduced-motion: reduce` 下停止一切循环动效，非循环动效退化为直接切换。

---

## 4. 结构骨架

**S1 · 两段式作答**　选话（候选）→ 落进输入区 → 按话筒译出 → 发送，四步顺序固定。选话只决定「说什么」，译出仍由玩家完成，系统不代译、不代发。

**S2 · 发送权归玩家**　发送永远由玩家亲手按下，不自动发送、不弹窗确认、不倒计时代发。

**S3 · 候选长在输入区里**　候选行与输入条共用底色与左轴线；待选 / 已落靠下划线区分。不另起面板，不加第二条边框。

**S4 · 候选上限**　聊天回合候选不超过三条；超过时改为从输入条上方展开的抽屉，抽屉收起后不占位。

**S5 · 不留空行**　选话态输入行必须有占位（提示语或光标位），不允许出现纯空行。

**S6 · 两种界面分工**　场景界面保留四行台词压在画面下三分之一；聊天界面用消息流。两者不混用，不在消息流里塞场景横幅。

**S7 · 构件式边框**　用窗框一类构件遮挡（有厚度、内阴影、遮住四角），不用 1px 细描边把界面框一圈。

**S8 · 取景框限定**　监视器取景框只用于真有监控 / 录像的段落，不作全局边框，不作装饰。

**S9 · 门禁按钮**　方键：直角、内凹边、按下整体下移 2px 并带内阴影、波形横排。取代「方底套圆环」。

**S10 · 图标规格（已定）**　16×16 网格，1px 线，最多 3 个实色（含描边与点色，透明不计）；分四类：状态、物件、动作、方向。**不做 emoji**，emoji 只可出现在台词内容里。

**S11 · 文案纪律**　不加说明性副标签与描述，让布局自己说话；错误只说明后果与下一步，不解释机制。

**S12 · 图标落地**　当前只锁定网格、线宽、色数与分类四项，不锁定具体画法；具体图形留到资产阶段，透视与笔画走向届时再定。

---

## 5. 禁止事项

1. 圆角、软阴影、模糊光晕、玻璃拟态。
2. 玫红铺面，或用玫红做正文与按钮底色。
3. 黄铜、金色、暖黄光。
4. 用 1px 细描边把整屏框一圈。
5. 全局监视器取景框。
6. 候选另起面板，或超过三条仍平铺。
7. 自动发送、发送前弹窗确认、倒计时代发。
8. 用 emoji 当图标或状态标识。
9. 说明性副标签、解释机制的错误文案。
10. 通过 CDN 加载像素字体。

## 6. 验收清单

- [ ] 所有大面积底色在 `#08070E`–`#2B2A3A` 区间内。
- [ ] 冷紫白只出现在门缝、灯光、焦点框与最高层级文字，每屏不超过两处。
- [ ] 玫红只以 1–2px 线与虚线框出现，没有铺面。
- [ ] 场景明度顺序为墙 < 地面 < 门 < 光。
- [ ] 中文正文 17px / 行高 26；像素字只用 24 / 36 / 48。
- [ ] 中英混排 baseline 对齐，行高统一 16。
- [ ] 盒模型尺寸与位移落在 4px 网格；描边为 1px。
- [ ] 界面上没有圆角、软阴影、模糊光晕。
- [ ] 作答四步顺序完整，选话后仍需玩家自己译出并按下发送。
- [ ] 候选与输入条共用底色与左轴线，靠下划线区分状态。
- [ ] 单回合候选不超过三条，超出走抽屉。
- [ ] 选话态输入行有占位，无纯空行。
- [ ] 场景界面四行台词压在下三分之一；聊天界面为消息流。
- [ ] 边框为构件遮挡，不是细描边包边。
- [ ] 取景框只出现在监控 / 录像段落。
- [ ] 门禁按钮为方键，按下下移 2px 带内阴影。
- [ ] 图标为 16×16、≤3 实色、四类分类，无 emoji。
- [ ] 图标只按四项规格执行，未锁死具体画法。
- [ ] 过渡为帧跳、转场为位移推，未对尺寸与颜色做插值。
- [ ] `prefers-reduced-motion` 下循环动效已停止。
- [ ] 界面无说明性副标签，错误文案只讲后果与下一步。
