# 真实语料扩容管线 设计规格

日期：2026-10-16
状态：已批准（用户确认方案 A 及全部设计节）

## 背景与目标

内置题库为 8 主题 × 各 20 句手写句子（共 160 句），用户希望扩容练习库，引入**真实语料**。本设计新增一条构建期抓取管线：本地运行 Node 脚本，抓取官方双语对照语料，经严格过滤后生成题库 JSON，随应用静态发布。

硬约束沿用主规格：应用保持纯静态 PWA、无后端。抓取发生在开发期（本地脚本），产品运行时零网络依赖。

## 需求澄清结论

| 决策点 | 结论 |
|--------|------|
| 语料类型 | A 政府文件类（官方中英对照）+ B 双语新闻类（官方翻译对照） |
| 质量把关 | 宁缺毋滥：脚本严格过滤，不合格直接丢弃，无人工审核环节 |
| 题库组织 | 新增独立主题，与现有 8 主题并列，各占一个题库文件 |
| 规模 | 起步版：每个新主题 50-80 句（低于 40 句视为失败） |
| 更新方式 | 手动运行命令重抓（无定时任务、无应用内更新入口） |

## 1. 主题与数据结构

- TOPICS 新增两项：`govreport`（政府文件）、`news`（新闻时事），与现有 8 主题并列。
- 新增题库文件：`src/data/library/govreport.json`、`src/data/library/news.json`。
- 句子结构与现有完全一致：`{ id, zh, en }`（`topic` 与 `source: 'builtin'` 由 sentences.js 运行时注入）。
- **id 稳定化**：id 由中文文本内容哈希生成（`gov_<sha256 前 8 位>` / `news_<sha256 前 8 位>`），不使用序号。同一句话在重抓/扩充后 id 不变，用户的练习记录与弱句标记得以延续。

### 前端改动范围

仅改 `src/lib/sentences.js`：TOPICS 数组加两项 + import 两个新 JSON。题库页、抽题、弱句复习、练习记录全部 id 驱动，自动兼容，零额外改动。

## 2. 抓取管线（构建期脚本）

- 新命令：`npm run fetch:corpus` → `node scripts/fetch-corpus.mjs`。
- 新 devDependency：仅 `cheerio`（HTML 解析用），不进应用产物。
- 流水线：抓列表页 → 逐篇抓正文 → 提取双语对照段 → 段落对齐 → 拆句 → 过滤 → 去重 → 截取限额 → 写入 JSON。
- 语料源（按优先级，抓取失败启用备选）：
  - govreport：政府工作报告双语版、外交部发言人记者会双语实录（官方逐段对照）
  - news：China Daily 双语频道（官方翻译对照）
- 过滤规则（硬编码于脚本）：
  - 长度：中文 ≤ 60 字，英文 ≤ 50 词
  - 剔除纯数字/符号句、含 URL 或邮箱的句子
  - 语言检测不通过的剔除（zh 字段须为中文、en 字段须为英文）
  - 按中文文本哈希去重
- 每主题截取上限 80 句，低于 40 句视为抓取失败。
- 代码结构：纯函数（拆句、过滤、语言检测、哈希 id、对齐校验）抽至 `scripts/corpus-lib.mjs`，供 Vitest 直接导入单测；`fetch-corpus.mjs` 负责网络与编排。

## 3. 容错与自校验

- 单篇抓取/解析失败：跳过该篇并输出警告，不中断整批。
- 最终句数 < 40（任一主题）：脚本以非零码退出并明确报错，**不写入半成品**（现有题库文件保持原样）。
- 写入前校验：所有句子 zh/en 均非空、id 唯一、topic 正确；校验不过即退出。
- 每主题只覆盖自己的 JSON 文件，其他主题文件不受影响。

## 4. 测试策略

- Vitest 单测覆盖 `corpus-lib.mjs` 纯函数：拆句边界、过滤规则、语言检测、hash id 稳定性、对齐校验。
- 集成验收：真实运行一次 `npm run fetch:corpus`，人工抽查产出样本句。
- 回归：现有 74 个测试全绿 + `vite build` 通过。
