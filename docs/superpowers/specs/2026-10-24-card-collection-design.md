# 抽卡收集设计

> 状态：待用户审阅 | 日期：2026-10-24 | 前置规格：`2026-10-14-interpret-practice-design.md`、`2026-10-18-voice.md`、`2026-10-19-speech-recognition.md`、`2026-10-21-retell-mode-design.md`、`2026-10-22-custom-sentence-management-design.md`（既定硬约束全部继承）

## 1. 背景与目标

练习流程本身已经稳定，但练完没有任何「发生了点什么」的反馈。长期使用后，练习变成一件没有情绪起伏的事。

本设计在练习之上加一层**抽卡收集**：练够句子拿到抽卡券，抽到一张角色卡，卡面被剪影遮住；你必须把这张卡绑定的一句「解锁句」口头译出来，剪影才会按你这次翻出的程度逐步露出。第一次抽到就一次翻对，还能解锁卡面的隐藏形态。

三个设计意图：

1. **奖励来自能力，不来自运气**——稀有度只决定抽到哪张卡，隐藏形态只由「第一次就翻对」决定。
2. **重复抽卡不浪费**——每次重复抽到的卡，都是一次重新冲击隐藏形态的机会。
3. **不增加压力**——抽卡券无上限、不过期，进度不倒退，没有体力值，没有「今天必须练」。

## 2. 范围

**做：**

- 练习计数 → 抽卡券 → 抽卡 → 剪影卡面 → 解锁练习 → 图鉴收集
- 卡片稀有度（普通 / 稀有 / 超稀有）与「连续重复后保底出新卡」
- 首次抽到即一次翻对 100% → 解锁隐藏形态
- 用户自带 API Key 的 AI 判分（含无 key 时的自评降级）

**不做（YAGNI）：**

- 抽到卡之后的角色互动 / 对话剧本（下一轮迭代）
- 真实立绘、卡面图片资源（第一版全部用 CSS/SVG）
- 体力值、十连抽、限时卡池、抽卡动画演出
- 抽卡历史页、单抽/十连的区分
- 服务端代理、账号体系、付费

## 3. 核心循环

```
练习一句 ──► 计数 +1（评分才计，跳过不计）
              ↓ 累计满 15 句（首张券为 5 句）
        得 1 张抽卡券
              ↓ 在练习页点「抽卡」
        消耗 1 券 → 抽到一张卡 ──► 卡面 0%（剪影 + 角色名）
              ↓ 进入解锁练习
        出示该卡的解锁句 → 口译 → 录音 → 五档自评（可选 AI 建议）
              ↓
        按本次档位露出剪影面积（不累加，取历史最高展示）
              ↓
    ┌─────────┴─────────┐
 100%                  < 100%
    ↓                     ↓
普通形态永久解锁      卡留在图鉴，可随时「继续解锁」
+ 若为本次抽卡的第一次尝试 → 同时获得隐藏形态
```

## 4. 抽卡券与计数

| 项 | 规则 |
|---|---|
| 计数时机 | 任何一次**评分**（普通练习的 ok/shaky/miss、解锁练习的五档）都 +1；点「跳过」不计 |
| 首张券门槛 | 累计练习 5 句（仅第一次） |
| 后续门槛 | 每 15 句 1 张券 |
| 券上限 | 无 |
| 券过期 | 不过期 |
| 进度显示 | 练习页头部显示 `当前进度/门槛`，例如 `12/15` |

计数在评分动作里同步累加，与 `addRecord` / `onRated` 同一处调用，不额外依赖页面生命周期。

## 5. 卡池与概率

### 5.1 卡池

第一版 8 张卡，静态数据打包，不写存储：

| 稀有度 | 张数 | 单抽概率 |
|---|---|---|
| 普通 | 4 | 70% |
| 稀有 | 3 | 26% |
| 超稀有 | 1 | 4% |

### 5.2 抽卡算法

```js
// 纯函数，rng 由调用方注入（测试可固定）
export function drawCard({ cards, owned, sinceNew, rng = Math.random }) {
  // 1. 连续 sinceNew >= 5 次抽到已拥有 → 保底出新
  const forceNew = sinceNew >= PITY_NEW_EVERY
  // 2. 决定稀有度：forceNew 时只在「还有未拥有卡」的档位里按权重抽
  //    ！forceNew = false 时正常按 70/26/4 抽；
  //      该档位内还有未拥有 → 抽未拥有；该档位全已拥有 → 抽已拥有（重复）
  // 3. 同档位内等概率
  return { cardId, tier, isNew }
}
```

- 保底计数 `sinceNew` 在抽到新卡时归零，抽到重复卡时 +1
- 保底语义精确为：**连续 5 次抽到已拥有 → 第 6 次必定出新卡**（`PITY_NEW_EVERY = 5`）
- 除「档位内优先抽未拥有」之外，不做任何额外权重倾斜
- 隐藏形态不影响抽取概率

### 5.3 终点

- 8 张全部解锁普通形态 **且** 8 个隐藏形态全部获得 → 抽卡按钮显示「全部收集完成」并禁用
- 在此之前抽卡按钮永远可用

## 6. 抽卡与卡面

### 6.1 入口

练习页头部（现有 `practice-header`）增加：

```
已完成 N · 12/15 · 券 ×2 · [抽卡]
```

券数为 0 时按钮禁用并显示「还差 3 句」。

### 6.2 抽卡结果

点抽卡后弹出全屏遮罩层（`DrawOverlay.vue`）：

1. 先显示卡背，短促翻面动画（0.3s）后落在剪影卡面
2. 卡面只显示：**角色名**、稀有度角标、`0%` 剪影轮廓
3. 下方两个按钮：`开始解锁` / `先放着`（关闭遮罩，卡存入图鉴，之后可继续解锁）

`prefers-reduced-motion: reduce` 时不做翻面动画，直接显示卡面。

### 6.3 剪影揭示

- 底层是完整卡面（第一版为 CSS 渐变 + 通用人形轮廓 SVG），上层盖剪影遮罩
- 遮罩挖出一个**不规则有机形状**的洞，洞的面积按 0 / 25 / 50 / 75 / 100 五档缩放
- 实现：`mask-image` 指向内联 SVG blob，`mask-size` 按档位缩放，`mask-position: center`
- 形状路径是第一版占位物，后续换更精致的撕裂/墨迹效果只换 SVG 路径，逻辑不动
- 展示取**历史最高档位**，只升不降

## 7. 解锁练习

### 7.1 入口与路由

新增路由 `/unlock/:id`（不在 TabBar 中）：

```js
{ path: '/unlock/:id', name: 'unlock', component: UnlockView }
```

- 从 `DrawOverlay` 的「开始解锁」进入
- 从图鉴里点未完成/未解锁的卡也进入这里
- 返回键 / 浏览器后退回到练习页

### 7.2 练习内容

- 句子来自卡片静态数据：`{ id: 'card_lin_unlock', zh, en, source: 'card', topic: 'card' }`
- 复用 `PracticeCard.vue`（录音、语音识别、参考译文、复述模式的既有能力全部继承）
- 方向固定为 `settings.direction`（与练习页一致）
- 评分区换成五档（`RatingButtons` 新增 `variant="unlock"`）：

| 按钮 | 进度 |
|---|---|
| 完全翻不出来 | 0% |
| 翻出一小部分 | 25% |
| 翻出大半 | 50% |
| 基本完整 | 75% |
| 完整流畅 | 100% |

### 7.3 评档的前置条件

- **必须先录过音**，评分按钮才出现（防纯点按钮）
- 录音能力不可用（`recorderSupported()` 为 false）时，直接显示按钮并在下方提示「本设备无法录音，本次为纯自评」
- 参考译文随时可看；**一旦看过参考译文，本次抽卡的隐藏形态资格即作废**（见 §9）

### 7.4 提交评分

一次评分 = 一次独立尝试：

1. 记录本次档位
2. `progress` 更新为 `max(旧值, 本次档位)`
3. `attempts += 1`
4. 计入练习计数（+1）、写入 `records.v1`、写入 `srs.v1`（与普通练习完全一致，不做特殊通道）
5. 更新剪影展示

`100%` → `unlocked = true`，永久保存。

## 8. 判定层

### 8.1 结构

判定是一个**可替换的计算层**，与渲染完全解耦：

```
输入：{ sourceText, referenceText, spokenText | null, selfBucket }
输出：{ bucket: 0|25|50|75|100, source: 'ai' | 'self', reason?: string }
```

### 8.2 AI 判分

- 设置页（`MeView`）新增三个输入框：`Base URL`、`模型名`、`API Key`，加一个「测试连接」按钮
- 只支持 OpenAI 兼容的 `/chat/completions`
- 请求内容：原文、参考译文、学生在语音识别中得到的文本；要求返回 `{"score": 0-100, "reason": "一句话"}`
- `temperature: 0`，超时 15s，失败重试 1 次
- 分数按就近映射到五档
- 识别文本在送评前**允许手动编辑**（修正识别错字），这是解决识别不准的主要手段

### 8.3 降级

以下任一情况走纯自评，界面标注「本次为自评」：

- 未配置 API Key
- 断网 / 请求失败 / 超时
- 语音识别不可用或没有识别文本
- 返回内容无法解析

### 8.4 软校验

- AI 档位与自评档位差距 ≥ 2 档（即 ≥ 50%）时，弹一次确认：「机器认为你翻出了 X%，确定按 Y% 解锁吗？」
- 差距 < 2 档时直接采用自评档位，不打扰

### 8.5 密钥安全

- `ai.v1` **不参与导出**，避免备份文件泄露密钥
- 设置页明示：密钥只存在本机浏览器，清缓存会丢失；识别文本会发送给你配置的服务商

## 9. 隐藏形态

- 定义：卡面的第二套外观（换配色 + 叠加效果），视觉由美术后续决定，数据上只是一个布尔
- 获得条件：**本次抽卡后的第一次解锁尝试**，档位 100%，且未看过参考译文
- 首次抽到的卡：第一次尝试 100% → 同时解锁普通形态 + 隐藏形态
- 第一次尝试未达 100% → 本次抽卡永久失去隐藏形态资格，只能等下次再抽到这张卡
- 已解锁普通形态的卡被重复抽到时：进入「隐藏挑战」模式——卡面完整显示，只判定本次第一发是否 100%，不展示剪影进度
- 已抽到但普通形态未解锁的卡被重复抽到时：继续普通解锁，不进入隐藏挑战

## 10. 数据模型

### 10.1 `progress.v1`

```js
{
  practiced: 0,      // 距下一张券的进度（0..14）
  total: 0,          // 累计已评分句数
  tickets: 0,        // 当前抽卡券
  earned: 0,         // 累计获得券数（用于判定首张券门槛）
  sinceNew: 0,       // 距上次抽到新卡的连续重复次数（保底用）
  draws: 0           // 累计抽卡次数
}
```

### 10.2 `cards.v1`

```js
{
  [cardId]: {
    attempts: 0,          // 本次抽卡后的已评分次数（0 = 还没试过）
    progress: 0,          // 当前尝试的历史最高档位 0|25|50|75|100
    unlocked: false,      // 普通形态永久解锁
    hidden: false,        // 隐藏形态已获得
    peeked: false,        // 本次抽卡是否看过参考译文
    lastAt: 0
  }
}
```

- 抽到一张已拥有的卡 → `attempts = 0`、`peeked = false`，其余字段保持
- 抽到一张新卡 → 新建条目，全部默认值

### 10.3 `ai.v1`

```js
{ baseUrl: '', model: '', apiKey: '' }
```

### 10.4 静态卡库 `src/data/cards.json`

```json
{
  "id": "lin",
  "name": "林",
  "tier": "super",
  "accent": "#7c6cf0",
  "unlock": { "zh": "……", "en": "……" }
}
```

- 解锁句 id 统一由 `card_<id>_unlock` 生成
- `source: 'card'`，无预生成音频，走浏览器 TTS 兜底

## 12. 边界与错误处理

| 情形 | 行为 |
|---|---|
| 券为 0 | 抽卡按钮禁用，显示还差几句 |
| 全部收集完成 | 按钮显示「全部收集完成」并禁用 |
| 存储不可用 | 券与卡不保存，提示「记录与收集进度不保存」，抽卡仍可查看结果 |
| 解锁练习中途退出 | 每次评分已落库，下次从图鉴继续 |
| 重复抽到已解锁的卡 | 进入隐藏挑战模式，不展示剪影进度 |
| 重复抽到未解锁的卡 | 继续普通解锁，不进入隐藏挑战 |
| 首次尝试看过参考译文 | 本次永久失去隐藏形态资格 |
| AI 未配置 / 失败 | 纯自评，标注「本次为自评」 |
| 录音不可用 | 允许自评，提示本设备无法录音 |
| 识别文本为空 | 跳过 AI 判定，走自评 |
| 卡库 JSON 损坏 | 抽卡按钮隐藏，不影响练习主流程 |
| 降低动效偏好 | 不做翻面动画，直接切换 |

## 13. 测试策略

单测（Vitest + happy-dom）：

- `cardpool.test.js`
  - 稀有度权重命中：注入固定 rng，验证 70/26/4 边界
  - 档位内优先未拥有、全拥有时返回重复
  - `sinceNew >= 5` 时必定返回新卡，且 `sinceNew` 归零
  - 全部拥有时不返回新卡且不崩
- `progress.test.js`
  - 首张券门槛 5、后续 15
  - 跳过不计数
  - 券累加、不清零进度
- `cards.test.js`
  - 首抽第一次 100% → `unlocked` 与 `hidden` 同时为真
  - 首抽第一次 50%、后续 100% → `unlocked` 真、`hidden` 假
  - 重复抽到已解锁卡 → `attempts` 重置、隐藏挑战生效
  - `progress` 取历史最高，不下降
- `grade.test.js`
  - 分数就近映射五档
  - 无 key / 请求失败 / 解析失败 → 降级 `self`
  - 软校验差异阈值：差 1 档不弹、差 2 档弹
- 组件测试
  - `CardReveal`：档位变化 → 露出面积变化；隐藏形态渲染不同
  - `RatingButtons` unlock variant：五个按钮、事件值正确
  - `UnlockView`：未录音不出现评分按钮；录音后出现；评分后进度更新
  - `MeView`：图鉴渲染、隐藏形态暗格、AI 配置保存

手工验收：

- 真机走完「练 5 句 → 首抽 → 解锁 → 100%」
- 连续 6 次重复抽卡验证保底出新生效
- 配一个真实 key 验证判分准确度与延迟
- 弱网 / 断网 / 错误 key 三种降级路径
